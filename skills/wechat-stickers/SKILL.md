# WeChatStickers

把已确认的角色做成完整可用的微信表情，而不止是分镜拼图。默认简体中文。依当前任务进入阶段：只要形象时不批量做表情，只要物料时不重做已确认角色。

## 1. 询问风格，设计形象（确认关口）

没有已确认形象时，**先问风格，再设计**。集中询问缺失的关键选择：喜欢哪类画风（如简约圆润、日系平涂、温暖手绘、夸张搞怪）、真人相似度与卡通化程度、有无参考。已有明确风格不重复问；不假定越幼稚越可爱。

结合参考确定脸型、发型、肤色/毛色、眼镜、服装、配色、比例和气质；职业、爱好只采用用户提供的信息。证件照只使用所需人像，不带出证件文字。使用可用的内置图像生成工具设计，不用程序几何图代替插画；环境提供 imagegen 技能时先读取并遵循。缺生成能力时说明限制，不悄悄换收费 API 或模型。

先交付清晰形象图和一句设计说明，**停下来等用户确认**。用户确认现成形象或明确授权沿用即可，不机械重复批准。确认后保存角色基准及“形象锁定表”，列不可改变的识别点。不要把头像的一次眨眼固定到所有表情。

## 2. 制作动态表情

确认专辑名、表情名称/数量、输出目录；缺列表时先提出适合角色的建议让用户确认。已给列表就完整执行，不漏做、不擅改静态。参数先读 [references/specifications.md](references/specifications.md)，动画和修订先读 [references/animation.md](references/animation.md)。

每款写动作计划：情绪/用途、姿势服装、道具、起势—主动作—停顿—回落、循环方式、固定锚点、小元素轨迹。款间差异来自动作和情境，不只是换字。先对少量高风险样例自查，不额外强制用户审批；通过再推进全套。分镜数量按复杂度选择，不固定四帧/六帧。

每次生成带已确认形象参考，锁定画风、配色、服装、镜头比例和视角。每款单独设计；分镜图不是最终 GIF。保留原图、提示词、选帧顺序、时长、裁切框和锚点，便于局部修订。

优先生成真透明；发现实色棋盘底需检查 alpha，使用环境提供并获准的背景去除技能/工具，不把棋盘格当透明。局部修图优先用图像编辑工具。白鞋、眼白、麻将牌面、浅色烟雾不能被一刀切删掉。本地处理不能绕过当前工具规则或授权。

## 3. 专辑物料

同一角色生成横幅、封面、聊天图标。按 [references/specifications.md](references/specifications.md)；头像、赞赏引导/致谢仅在当前范围包含时制作。按需要提供专辑名和 80 字以内简介，不擅自改用户命名。

横幅用与角色/表情相关的故事场景，明快的不透明底色，安全区构图，不拉伸。封面用正面半身/全身、少道具；图标单独设计头部，检查实际 50 像素效果，不把复杂整张缩小。默认不加字；明确要横幅文案时按原文设计，并提示与已有无字提交要求的冲突，由当前要求决定，不能悄悄删字。

## 4. 导出、验收、交付

机械导出先读 [references/export.md](references/export.md)，可用 scripts/export_assets.py；它只处理已经生成、抠好的图像，不绘画、不抠图、不判断动作连贯。首次看 --help。缺依赖申请或说明，优先项目虚拟环境，不修改全局环境。

同款固定比例和身体/场景锚点，**不得按每帧外接框独立缩放居中**。允许真实动作位移，不为“稳”冻结头和手。字幕固定排版。逐帧检查和实际循环预览都要做；规格通过不等于视觉通过。检查深浅背景、残边、跳帧、道具连续性、颜色及情绪可读性。没有动画播放能力时明确只做了逐帧检查，不能声称已看过动态播放。

分类交付角色基准、GIF 成品、缩略图、提交物料、非提交预览、制作源文件。按用户指定本地目录保存；没指定用当前项目并报真实绝对路径。新版本保留旧成品，不覆盖来源不明修改。ZIP 做完整性检查，提供下载、动态预览、简短规格；提示词/检查记录存来源目录。

只有实际产出、可读取、规格和必要视觉检查完成才称交付。微信上传、GitHub 发布、安装依赖、关机是独立操作，需要当前授权；“全套做完”不自动授权。发布此技能时只包含通用说明、脚本、匿名测试，排除用户照片、证件、成品、凭证和私人路径。
